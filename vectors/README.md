# Vectors

`spec/` holds byte-for-byte copies of Marmot spec documents the
implementation is tested against — frozen at the spec rev pinned in
`upstream.json` (`spec.rev`, currently `f825024`). Do not edit them; they
move only when the pin moves. `bun run check:pins` verifies them against a
local `3rdparty/marmot` checkout when present.

- `spec/foundation/registries.md` — every registered id (component ids,
  extension types, event kinds, ALPN, exporter labels). Parsed by
  `packages/marmot/tests/registries.test.ts`, which asserts set-equality with
  the constants in `src/core/registries.ts`.
- `spec/foundation/errors.md` — the shared result/rejection vocabulary
  (input categories, dispositions, named outcomes). Parsed by
  `packages/marmot/tests/errors.test.ts` the same way.

- `bridge/` — canonical JSON encodings for the `mk-bridge` host protocol,
  one file per wire enum plus `config.json`/`call.json` envelopes (see
  `bridge/README.md`). `crates/mk-bridge/tests/vectors.rs` round-trips every
  entry and checks the key set equals the serde-derived variant set, so a
  variant without a vector fails the suite.

Shared cross-language test vectors (MDK conformance replays, our own) land
here alongside `parity.json` in later milestones.

- `mdk/` — byte-for-byte copies of the MDK cgka-conformance-simulator vector
  fixtures (top-level `*.v1.json`, `incidents/*.json`, `manifest.v1.json`),
  frozen at the MDK pin in `upstream.json` (`mdk.rev`, tag `v0.17.0`).
  Provenance (repository, tag, rev, source path, SHA-256 per file) lives in
  `mdk/PROVENANCE.md`; `bun run check:pins` verifies the copies against a
  local `3rdparty/mdk` checkout when present. `crates/conformance` replays
  them through the public `Session` API. `mdk/encrypted-media/` holds
  byte-for-byte copies of MDK's `fixtures/encrypted-media/imeta-v{1,2}.json`
  (strict `imeta` parser accepted/rejected cases); `crates/mk-core`'s
  `tests/media.rs` replays them through `media::parse_imeta`.

- `encrypted-media/` — our own vectors, not upstream copies.
  `v2-crypto.json` is an independent Python implementation of the
  encrypted-media-v2 key schedule and AEAD (generated by the committed
  `gen-v2-crypto.py`; do not edit the JSON by hand — regenerate with the
  script). Its `mdk-kdf-aad` case equals MDK's own literal KAT;
  `tests/media.rs` checks every case against `media::derive_file_key`,
  `media::media_aad`, `media::encrypt_file` and `media::decrypt_file`.

# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

A `vX.Y.Z` tag runs `publish-npm.yml` (publishing `packages/marmot` via npm
trusted publishing / OIDC).

## [Unreleased]

### Added

- Repository skeleton: bun + vite-plus workspace, `@qntx/oxlint` /
  `@qntx/oxfmt` / `@qntx/tsconfig`, empty Cargo workspace with shared lint
  profiles, lint-enforced `packages/marmot` layer graph, lockstep version
  tooling, `qntx/workflows` CI and release workflows.
- `@qntx/marmot` core registries and result vocabulary mirroring the Marmot
  spec at `f825024` (app component ids, extension-draft ids, extension types,
  event kinds, ALPN identifiers, exporter labels; input categories,
  dispositions, named outcomes), tested against byte-for-byte recorded spec
  copies under `vectors/spec/foundation/`.
- `upstream.json` pins (`spec` marmot-protocol/marmot `f825024`, `mdk` v0.18.0
  `34646a5`) and `bun run check:pins`, which verifies local `3rdparty/`
  checkouts and the recorded spec copies.
- `crates/mk-core`: a persistent key-value `cgka_traits::StorageProvider`
  for the pinned MDK engine (one key encoder, serde_json values,
  transactions/savepoints/read snapshots, snapshot/checkpoint restore,
  durability gate) and a public `Session` API — two-phase account open,
  key-package/inbox-relay publishing, group create/invite/remove/leave/
  self-update/profile/app-components, message send, ingest (batched,
  newest-first), tick-driven convergence, staged outbox with
  per-outbound publish resolution — over injected `KvHost`,
  `AccountSigner` and `Clock` traits.
- `crates/conformance` (standalone): replays the recorded MDK scenario
  vectors under `vectors/mdk/` through the `Session` API and classifies
  each `PASS`/`REFUSED`/`BYTE-FIXTURE`.
- `crates/interop` (standalone): wn/wnd scenario tests against the public
  `Session` API over an in-process NIP-01 relay (`#[ignore]`d; need
  `WN_BIN`/`WND_BIN`).
- mk-core White Noise v0.16.0 parity: `0x8006` agent text stream
  (receive-role) and `0x800b` encrypted-media-v2 components advertised;
  strict `imeta` parsing/projection (`ReceivedMessage::attachments`,
  `stream_final`), `AgentStreamStarted` anchors, per-message exporter
  secrets persisted under `(group, transport)` and cleared on
  invalidation/group deletion, `seal_attachment`/`send_media`/
  `open_attachment` media APIs with epoch pinning, `CreateGroup.components`,
  `drain_events` -> `Result`, and `RelayPolicy` renamed to
  `DestinationPolicy` shared by relay and blob destinations.
- `fuzz/` (standalone): seven libFuzzer targets covering every mk-core
  decoder; seed corpus generated by `gen_corpus`.
- mk-core test suites: model/proptest parity against `storage-sqlite`,
  nine-boundary crash-consistency tests, session flow tests, conformance
  vectors, and an engine-level reproduction test for an upstream MDK
  defect (`AlreadyExists` on re-confirm of a deterministic own commit
  after convergence rewind — handled as typed `ConfirmConflict`).

### Changed

- MDK pin `v0.16.0` (`a2e0558`) → `v0.17.0` (`4df811a`); the spec pin is
  unchanged at `f825024`.
- MDK pin `v0.17.0` (`4df811a`) → `v0.18.0` (`34646a5`), `wn` pin likewise.
  `crates/mk-core` store schema version 5 → 6 for the new
  `ChangeNotDelivered` table and upstream's new stored-payload variants
  (old builds must refuse the new database).
- `crates/mk-core` store schema version 2: the `MessageState` index now
  keys `[group, state, epoch, seq, message-id, content-class, epoch]` with
  empty values and `MessageIndex` maps message-id to that key, so every
  message listing, existence probe, content-filtered listing, early-exit
  visit, deferred-metadata scan, group delete and full-snapshot capture
  answers from index keys and decodes only the rows it returns. Stores
  written by schema version 1 refuse to open
  (`OpenError::UnsupportedSchemaVersion`); `mk_core::testing` gains
  `check_message_index`, which verifies the index tables match the stored
  message rows exactly.
- `crates/mk-core` row encoding: `serde_json` stays the one codec for
  every row value and key, but mk-core-owned row structs — the stored
  message row (a `MessageRecord` mirror) and the snapshot blob's byte
  fields — now carry `Vec<u8>` fields as standard base64 strings instead
  of decimal arrays, roughly halving stored row sizes; outbox
  publication and inbox-relay row values route through the shared
  encode/decode helpers.

### Fixed

- `crates/mk-core`: `stored_key_package_bundles` now returns the bare
  entity bytes in `StoredKeyPackageBundle::value` — matching sqlite and
  what `cgka-engine` parses with
  `serde_json::from_slice::<KeyPackageBundle>` — instead of the framed
  `[group_key][entity]` row, which no consumer could decode.
